## 1. このプロジェクトは何か

「ハーベストケア」という介護施設（デイサービス・住宅型有料老人ホーム・居宅介護支援）の
**静的サイト**（サーバー側のプログラムを持たない、HTMLファイルだけのホームページ）。
GitHub Pagesで公開されている前提で作られている。ビルド工程（変換作業）は一切ない。
HTMLを直接編集し、プッシュすればそのまま公開される。

## 3. 報告メモアプリ（houkoku-memo.html）の仕様

職員が各自のスマホで介護記録メモを取り、共有・統合して日報を作るツール。
**1ファイル完結**（HTML+CSS+JSすべて同一ファイル内）。外部ライブラリなし。サーバーなし。

### 設計の考え方
- データは各スマホの `localStorage`（ブラウザ内の保存領域）に保存。
- 端末間の共有は「共有テキスト」をLINE等で送り合い、貼り付けて取り込む方式。
  サーバー不要でGitHub Pagesのまま動かすための意図的な設計。**安易にサーバー化しないこと**
  （個人情報を扱うため、外部サーバーに載せるならセキュリティ検討が必須になる）。

### データ仕様（変更時は後方互換に注意）
- 保存キー: `hc_memo_entries`（メモ配列）、`hc_memo_laststaff`（前回の職員名）
- メモ1件のスキーマ（形式）:
  ```json
  { "id": "英数字", "date": "YYYY-MM-DD", "time": "HH:MM",
    "staff": "職員名", "resident": "利用者名", "category": "分類",
    "important": true, "text": "本文", "updatedAt": 1234567890 }
  ```
- 分類: 体調・様子 / 事故・ヒヤリ / 食事・水分 / 排泄 / 入浴 / 服薬 / 家族連絡 / その他
- 共有テキストの形式: 人間が読める要約 ＋ `HCMEMO1:` に続くbase64（文字列を英数字に
  変換したもの）のJSON配列。取り込み時は `id` で重複判定し、`updatedAt` が新しい方を採用。
  **`HCMEMO1:` という目印とこのマージ（統合）規則は互換性の要。変えるなら旧形式も読めるようにすること。**
- 音声入力: Web Speech API（`webkitSpeechRecognition`、言語 `ja-JP`）。HTTPS必須。
- 印刷: `#printArea` にテキストを入れて `window.print()`。印刷時は本体を隠すCSSあり。

### 動作確認の実績
2026-07-05 にヘッドレスブラウザ（画面なしで動かすChrome）で以下を確認済み:
保存→一覧表示 / 重要フラグ集計 / 共有テキスト取り込み / 二重取り込み防止 / 日報生成。

## 4. 作業の進め方（Fable 5からの申し送り）

1. **報告前に自分で検証する。** HTMLを変えたら最低限 `node --check` でJS文法を確認し、
   できればヘッドレスChromium（`/opt/pw-browsers/` にある）で実際に操作して確かめる。
2. **学んだことは `MEMORY.md` に追記する。** セッションをまたいで知識を残す唯一の場所。
3. コミットメッセージはこのリポジトリの流儀に合わせる:
   `ファイル名: 変更内容の要約（日本語）` 例: `caremanager.html: 地図ピン修正`
4. 作業ブランチ（作業場所）が指定されている場合はそこで開発し、指定がなければ
   新しいブランチを切る。mainに直接プッシュしない。
5. ユーザーへの報告は「何ができるようになったか」を先に、技術的な話は後に短く。
